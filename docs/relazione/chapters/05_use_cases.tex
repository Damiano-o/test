\chapter{Use Cases}\label{ch:usecases}

This chapter presents the use-case model of CiboAmico. The overview diagram
\ref{fig:ucd} shows the system boundary, the four primary actors, and the
external actors \emph{OpenFoodFacts} and \emph{Payment Service}. Each use case
is described with preconditions, postconditions, main success scenario (MSS)
and extensions. All steps are written in the simple present with active verbs;
no GUI detail is included. Use case \textbf{UC-10} (grey in the diagram) is
excluded from the evaluation scope: it documents a domain capability that is
not implemented, keeping the numbering continuous and the model coherent with
the code.

\section{UC-04 Order a Product (exemplary template)}
\label{sec:uc04}

\textbf{Actors:} Client (primary), Payment Service (external).

\textbf{Preconditions:} the Client is authenticated; the product is published
on the marketplace; the inventory of the vendor contains the requested
quantity.

\textbf{Postconditions:} an order in the \emph{CREATED} state is recorded for
the buyer and the vendor; the vendor receives a notification.

\textbf{Main Success Scenario (MSS):}
\begin{enumerate}
    \item The Client selects a product from the marketplace.
    \item The System verifies the availability of the product.
    \item The System shows the order summary with the total price.
    \item The Client confirms the order.
    \item The System records the order with state \emph{CREATED}.
    \item The System notifies the vendor of the new order.
\end{enumerate}

\textbf{Extensions:}
\begin{itemize}
    \item \textbf{2a. Product out of stock:}
    \begin{enumerate}
        \item The System notifies the Client of the product unavailability.
        \item The flow returns to step 1.
    \end{enumerate}
    \item \textbf{5a. Invalid state transition (BR-04):}
    \begin{enumerate}
        \item The System rejects the transition and keeps the previous state.
    \end{enumerate}
\end{itemize}

\section{Other Use Cases (summary)}

\subsection*{UC-01 Manage Inventory}
\textbf{Actors:} Client. \textbf{Pre:} authenticated.
\textbf{MSS:} (1) the Client provides product data; (2) the System validates
the data (FR-01); (3) the System stores the product in the inventory;
(4) the System confirms. \textbf{Extensions:} 2a missing mandatory data; 2b
invalid quantity. \textbf{Post:} product stored and visible in the expiry-
ordered list (FR-02).

\subsection*{UC-02 Find Compatible Recipes}
\textbf{Actors:} Client. \textbf{Pre:} inventory not empty.
\textbf{MSS:} (1) the System retrieves the inventory; (2) the System retrieves
the approved recipes; (3) the System matches ingredients (strict or with
substitutions, D-01); (4) the System presents the compatible recipes.
\textbf{Post:} the client sees only the feasible recipes.

\subsection*{UC-03 Compute Shopping List}
\textbf{Actors:} Client. \textbf{Pre:} a recipe exists and is approved.
\textbf{MSS:} (1) the Client selects a recipe; (2) the System retrieves the
recipe and the inventory; (3) the System compares the recipe ingredients
with the inventory (strict or with substitutions, D-01); (4) the System
presents the missing ingredients with quantities. \textbf{Post:} an exact shopping list is shown
(FR-05).

\subsection*{UC-05 Publish Product}
\textbf{Actors:} Vendor. \textbf{Pre:} vendor approved (BR-02).
\textbf{MSS:} (1) the Vendor provides product data with price; (2) the System
validates price and expiry (BR-06, BR-01); (3) the System publishes the
product. \textbf{Extensions:} 2a price $\leq 0$; 2b expired product.

\subsection*{UC-06 Manage Received Orders}
\textbf{Actors:} Vendor. \textbf{Pre:} at least one order exists for the
vendor. \textbf{MSS:} (1) the System presents the orders in \emph{CREATED} or
\emph{CONFIRMED} state; (2) the Vendor updates the state of an order;
(3) the System validates the transition (BR-04); (4) the System stores the new
state and notifies the buyer. \textbf{Extensions:} 3a invalid transition.

\subsection*{UC-07 Create Recipe}
\textbf{Actors:} Nutritionist (the only role allowed). \textbf{Pre:}
authenticated as nutritionist. \textbf{MSS:} (1) the Nutritionist provides the
recipe with at least two ingredients (BR-05); (2) the System creates the
recipe in \emph{PROPOSED} state; (3) the System stores the recipe.
\textbf{Extensions:} 1a fewer than two ingredients.

\subsection*{UC-08 Manage Pending Approvals}
\textbf{Actors:} Administrator. \textbf{Pre:} administrator authenticated.
\textbf{MSS:} (1)~the Administrator requests the pending approvals;
(2)~the System retrieves the categorised list of pending vendor registrations
and recipes in \emph{PROPOSED} state; (3)~the Administrator selects a pending
item; (4)~the System presents its details; (5)~the Administrator approves,
suspends or rejects the item; (6)~the System updates the state, notifies the
interested actor and confirms. \textbf{Extensions:} 2a empty queue; 5a
rejection/suspension returns to step 2. \textbf{Post:} item status updated
(APPROVED/SUSPENDED for vendors, APPROVED/REJECTED for recipes).

\subsection*{UC-11 Authenticate}
\textbf{Actors:} Client, Vendor, Nutritionist, Administrator. \textbf{MSS:} (1) the Actor provides
e-mail and password; (2) the System validates the credentials (NFR-03);
(3) the System opens a session. \textbf{Extensions:} 2a invalid credentials.
\textbf{Post:} the session is active; \emph{include} from UC-04, UC-05, UC-06 (as in the diagram).
